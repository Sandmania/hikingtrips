## Why

The trip index page renders cards via an imperative `renderTripCards()` function in `index.js` with trip data hardcoded in the same file. Moving to declarative web components and a static JSON manifest makes the data easy to maintain, aligns with the component architecture used elsewhere in the project, and sets up a clean deploy-time generation workflow.

## What Changes

- Introduce `<trip-grid>` custom element (shadow DOM organism) that fetches `trips.json` and renders trip cards
- Introduce `<trip-card>` custom element (shadow DOM organism) that renders a single trip card given trip data as a property
- Add `trips.json` at the project root as the data source for trip cards (auto-generated by deploy script)
- Add a deploy script that populates `trips.json` from each trip's `trip_config.yaml`
- Remove `renderTripCards()` from `assets/js/index.js` and the hardcoded trips array
- Migrate trip card and grid CSS from `assets/css/index.css` into shadow DOM component styles
- Replace `<div id="trips-grid">` in `index.html` with `<trip-grid>`

## Capabilities

### New Capabilities
- `trip-grid`: A `<trip-grid>` custom element that fetches `trips.json` and lays out `<trip-card>` elements in a responsive grid
- `trip-card`: A `<trip-card>` custom element that renders a single trip card — hero image background, title, dates, and a link to the trip hash route

### Modified Capabilities

## Impact

- `assets/js/index.js`: `renderTripCards()` and hardcoded trips array removed
- `assets/css/index.css`: Grid and card styles migrate into component shadow DOM; body background style remains
- `index.html`: `<div id="trips-grid">` replaced with `<trip-grid>`; component scripts added
- New files: `assets/components/tripGrid/TripGrid.js`, `assets/components/tripCard/TripCard.js`, `trips.json`, `scripts/generate-trips-manifest.js`
- `assets/js/router.js`: may need updating if it references `renderTripCards()`
